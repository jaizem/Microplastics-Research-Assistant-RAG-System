rate)\n- Wrong flags, argument order, malformed syntax\n- Limited usefulness in agentic workflows\n\n### Solution\n**Grammar-Constrained Decoding**: Apply formal grammar constraints *during* token-by-token generation\n\n```\nModel Logits: [5.2, 3.1, 4.8, 2.1, -0.5, ...]  (for 10k tokens)\n           ↓\nGrammar Mask: [1,   1,   1,   0,   0,   ...]  (which tokens allowed?)\n           ↓\nMask Application: [5.2, 3.1, 4.8, -∞, -∞, ...]  (zero out forbidden)\n           ↓\nConstrained Distribution: Only valid tokens have probability\n           ↓\nSample: Get syntactically valid next token\n           ↓\nRepeat: For each position in sequence\n```\n\n### Results\n- **Qwen3-0.6B**: 16.7% → 59.2% (+42.5 pts)\n- **Average across 13 models**: 62.5% → 75.2% (+12.7 pts)\n- **Cost**: Minimal overhead (1-2% latency)\n\n### Implementation\nThis tutorial teaches:\n1. **Why**: Constrained decoding theory\n2. **How**: Token masking mechanics\n3. **What**: Grammar generation from data\n4. **Build**: End-to-end pipeline\n5. **Deploy**: LangChain integration\n\n---\n\n## 📖 Documentation Map\n\n**For different questions, consult:**\n\n| Question | File |\n|----------|------|\n|
